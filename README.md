# Production Control API

API для контроля заданий на выпуск продукции: партии, продукция, агрегация, отчёты, импорт/экспорт и вебхуки.


## Запуск

```bash
docker compose up --d
```

Сервис `migrate` сам применяет миграции (`alembic upgrade head`) и создаёт бакеты в MinIO.

| Сервис | Адрес |
|---|---|
| API и Swagger | http://localhost:8000/docs |
| Flower (Celery) | http://localhost:5555 |
| RabbitMQ UI | http://localhost:15672 |
| MinIO console | http://localhost:9001 |
| Приёмник вебхуков (для проверки) | http://localhost:5000 |

## Настройки

Переменные окружения описаны в `.env.example`. Важные:

- `PRODUCTION_TIMEZONE` - часовой пояс производства. Время без смещения в запросах и файлах считается временем этого пояса.
- `SMTP_*` - отправка отчётов по почте. `SMTP_STARTTLS` и `SMTP_LOGIN` можно отключить для локального SMTP.

## Основные сценарии

Все маршруты имеют префикс `/api/v1`. Лимит запросов - на уровне приложения (slowapi).

**Партии** (`/batches`)
- `POST /` - создать партии списком. Ответ: `{created: [...], errors: [{row, error}]}`. Дубли попадают в `errors`.
- `GET /`, `GET /{id}`, `PATCH /{id}` - список с фильтрами, одна партия, изменение. При закрытии партии ставится `closed_at`.
- `GET /{id}/statistics` - статистика по партии.

**Агрегация**
- `POST /batches/{id}/aggregate` - синхронно, тело `{"unique_codes": [...]}`.
- `POST /batches/{id}/aggregate-async` - в фоне, возвращает `task_id`.

**Отчёты** - `POST /batches/{id}/reports`, тело `{"format": "excel" | "pdf", "email": "..."}`. Файл кладётся в MinIO; если указан `email`, письмо отправляется с вложением (статус отправки в поле `email_status` результата задачи).

**Импорт и экспорт** (CSV и XLSX)
- `POST /batches/import` - загрузка файла. Заголовки: `НомерПартии`, `ДатаПартии`, `СтатусЗакрытия` (`Открыта`/`Закрыта`), `ПредставлениеЗаданияНаСмену`, `РабочийЦентр`, `ИдентификаторРЦ`, `Смена`, `Бригада`, `Номенклатура`, `КодЕКН`, `ДатаВремяНачалаСмены`, `ДатаВремяОкончанияСмены`. Ошибки отдельных строк попадают в результат, ошибка файла (неизвестные заголовки, пустой файл) завершает задачу как FAILURE.
- `POST /batches/export` - выгрузка с фильтрами в том же формате, что принимает импорт.

**Задачи** — `GET /tasks/{task_id}` - статус и результат фоновой задачи.

**Вебхуки** (`/webhooks`) - управление подписками и просмотр доставок. Неудачные доставки повторяются по расписанию (каждые 15 минут, до `retry_count`).

**Аналитика** (`/analytics`) - дашборд и сравнение партий.
